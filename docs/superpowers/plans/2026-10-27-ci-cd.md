# GitHub Actions CI/CD Implementation Plan

> Execute inline with the executing-plans skill; validate deployment behavior before enabling production access.

**Goal:** Test the project, publish its AMD64 image to Docker Hub, and deploy a selected build to the existing Timeweb VPS.

**Architecture:** One workflow runs tests and builds the Dockerfile. Main pushes publish images; manual runs on main can additionally deploy over SSH using a production environment. Production retains its existing Compose configuration and secrets.

**Tech stack:** Java 21, Gradle, PostgreSQL 16, Docker Buildx, GitHub Actions, Bash, Python 3, SSH.

**Spec:** Conversation: Docker Hub repository `vfadeevdocker/fin-assist`; production host `2.59.42.251`; HTTPS domain `fin-assist.st-novator.ru`. Manual deployment is the initial default. Confirmed SSH user `deploy`, project directory `/root`; user authorized preparing a restricted root-owned deployment command and installer.

## Constraints and review focus

- Pull requests must not publish images or receive production credentials.
- Deploy the build's digest; do not resolve a mutable latest tag at deployment time.
- Serialize production deploys and never cancel an active deployment.
- Preserve database/storage volumes and server secrets. Do not automate database rollback.
- Failed pulls must not restart services; failed health checks must fail the job without recording success.
- Persist the successful image selection for later Compose operations; refresh Nginx after container replacement.

## Decisions

- Work on a feature branch in the existing checkout; no additional worktree or production changes are needed to prepare the configuration.
- SSH credentials and Docker Hub token will be configured by the user in GitHub, never committed.
- Do not publish the workflow or run a production deployment until server configuration is supplied and the prepared result is reviewed.
